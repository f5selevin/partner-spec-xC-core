F5 Distributed Cloud HTTP Load Balancer Basics
########################################################


These exercises use the **Arcadia Crypto** application.

This application is a modern application simulating a crypto trading platform app where you can buy and sell crypto currency.

The Arcadia Crypto application is deployed in UDF in two ways:

* **Arcadia Crypto - Cluster** - a service cluster that is publicly available on the internet
* **Arcadia Crypto - OnPrem - K8S** - an on-premises Kubernetes installation that is not publicly available and will be used in the Multi-Cloud Networking exercises to create MCN connections

The following components are used within the application:

* **Frontend** - serves the non dynamic content for like html, js, css and images
* **Login** - is in charge of dealing with anything related to the login user functionality
* **Users** - all user data interaction is done through this microservice only
* **Stocks** - connects to external resources to get the latest crypto data and serves it to the application clients
* **Stocks Transaction** - Deal with all related to buying or selling crypto currencies. It interact with other microservices like Users and Stocks
* **Database** - Database were all information is stored

In this section, you will:

* Create three origin pools for the public Arcadia Crypto endpoints and publish the application through an F5 Distributed Cloud HTTP load balancer
* Configure and verify round-robin traffic distribution across the three origin pools
* Configure a Web Application Firewall (WAF), test it with an XSS attack, and investigate the blocked request in Security Analytics
* Enable IP Intelligence for spam sources and anonymous proxies, and verify that traffic from a public proxy is blocked
* Configure Malicious User Detection using the Authorization header and client IP address as user identifiers
* Generate malicious authenticated and unauthenticated traffic, examine detected users, and add a blocked user to the allow list
